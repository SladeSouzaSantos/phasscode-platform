## Estratégia de custo, precisão e atualização

1. **Índice no processo:** o Orbe carrega `knowledge/portfolio.json` uma vez ao iniciar, e seleciona no máximo cinco documentos por pergunta comum. Não consulta o MCP nem transfere todo o repositório para o modelo.
2. **Busca lexical controlada:** termos, tecnologias e intenção da vaga identificam evidências curadas; o código complementa a classificação com âncoras para Java, React/QA, IA, dados, Flutter, DevOps e energia.
3. **Aprofundamento opcional:** consultas expressamente sobre README, código e repositório podem ler trechos públicos limitados, de até dois repositórios, sem acesso a credenciais ou URLs arbitrárias. Trechos externos não são fonte de instruções nem substituem o índice curado.
4. **Atualização periódica supervisionada:** usar integração GitHub/MCP **fora do caminho de cada mensagem**, detectar revisão dos projetos importantes, comparar `README`, manifests e testes, revisar autoria/status e atualizar este índice e `portfolio.json`. Não incluir segredos ou código confidencial; cada entrada deve separar provas, alegações e ausências de confirmação.
5. **Custos:** MCP facilita acessar repositórios; **não reduz tokens por si só**. O índice curto diminui chamadas HTTP e volume de contexto por resposta. Embeddings/banco vetorial só se justificam quando a busca lexical não sustentar precisão mensurável.
6. **Homologação:** `npm run check` e testes de regressão com perguntas de recrutadores; testar a resposta com LLM real separadamente, pois testes com provider simulado validam a recuperação, não garantem o texto gerado.

## Lacunas já descobertas na auditoria com recrutadores

- Confusão ACRUX/SIGAA: Java+H2/NetBeans versus Java+Hibernate/JBoss/PostgreSQL.
- Afirmação de que PHASSCODE não usa LangChain: incorreta; usa `@langchain/openai`, mas não RAG vetorial no produto atual.
- Afirmações de inexistência de testes de frontend e uso atual de Cypress: incorretas; usa Playwright e `@axe-core/playwright`. Cypress consta como curso.
- Não atribuir armazenamento permanente de dados ou validação física certificada ao HSP Simulator sem fonte.
- Falha de conexão no sétimo cenário de entrevista real: não diagnosticar como falha de LLM nem de rede sem o respectivo código/correlação; revisar logs/telemetria se reaparecer.
